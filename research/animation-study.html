Motion on Done, Delete and Back

The app has no motion in it anywhere. A key is pressed, a request goes, a new page arrives — and on the screens where the same key is pressed over and over, the new page is the same shape as the old one with a different item in it. Press Done twice and two actions are completed, the second one never looked at. Nothing on the screen says the first press landed, because the screen after it is the screen before it.

Eight treatments, live and pressable. Pick a moment, then press a tile — and press it twice, fast, which is the whole question. The counter under each screen says how many items that double press actually consumed.

What each one costs

Three families, and what separates them is where the time goes. A leaving effect runs before the swap, so the item that was acted on is still on the screen while it plays — that is what makes the press unmistakable, and it is the only family that swallows the second press by itself. An arriving effect runs after the swap and costs nothing, because the new page is already there. An overlay costs nothing either, and is the only one that says which of the three things happened.

The zero is not free of the problem. An arriving effect cannot swallow the second press, because by the time it plays that press has already been sent. Either family needs the key to go deaf for anim.ms after it fires — a leaving effect gets that for nothing, an arriving one has to be given it.

The settings

Three keys, because the three moments make three different claims. Done is a thing finished, delete is a thing thrown away, back is a place left — and the motion that says one of them says the other two wrong. One duration for all three, because that is not about the moment, it is about the hand. 

# what each of the three moments looks like; "none" is what the app does now
anim.done   = strike     # none fade strike collapse sweep rise flash stamp
anim.delete = collapse   # none fade        collapse sweep rise flash stamp
anim.back   = sweep      # none fade                 sweep rise       stamp
anim.ms     = 160        # how long any of them runs, 0 to 600; 0 is "none" on all three

The three lists are not the same, and the file refuses a value that has no meaning for its key — the rule every string setting in conf.go already keeps, for the reason stated there: a settings file is read once, so a typo quietly ignored is a setting that looks set for as long as the process lives. strike is not offered on a delete, because a line through a title is the mark for finished and putting it on a thing being thrown away says the wrong word. collapse and flash are not offered on back, because nothing is removed and nothing new is acted on — the screen is simply somewhere else.

The file is the only switch. The system's own "reduce motion" is not consulted: this is one app on one desk, and a file that says anim.done = strike is a more specific answer than a preference set once for everything on the machine. Turning all of it off is anim.ms = 0, one line.

Where it would live

  • The body is boosted — hx-boost="true" in _layout.html — so none of these is a page load: htmx already fetches the new page and swaps the body. A leaving effect goes on at the press and the request follows it, rather than the two running together: a browser goes on painting the old page until the answer commits, so firing both at once cuts the effect off after the few milliseconds a server on this machine takes — the one arrangement where the motion is paid for and never seen. The cost is anim.ms plus a local request.
  • What just happened travels the way the cursor already does. The keyboard layer hands the selected row and the scroll offset to the next page through sessionStorage (kb-row-handover and kb-place-handover in app.js). An arriving effect is one more handover of that exact shape: which of the three moments this page was reached by, claimed once on arrival and cleared.
  • The deaf window is the fix; the motion is the explanation. While an effect is running, rowCommand answers d, ⌫ and b by doing nothing and reporting the key as handled. That is what stops the second press. The animation is what stops it from being needed again.
  • All three docs. design.md gets why a moment shows itself at all; implementation.md gets the effects, the settings keys and the swap delay; keys.md gets the deaf window, because "this key does nothing for 160 ms" is a fact about what a key may be.

What I would pick

anim.done = strike · anim.delete = collapse · anim.back = sweep · anim.ms = 160

Each one says its own word rather than a general "something happened": a line drawn through a title is what finished looks like everywhere, a thing folding shut while the list closes over it is what thrown away looks like, and a screen sliding aside is what leaving looks like. All three are leaving effects, which is the point — they are the only family that makes the second press impossible with no extra machinery, and 160 ms is under the threshold where a press stops feeling instant and over the one where an effect is not seen at all.

If that reads as too much movement after a week of living with it, the quieter answer is fade on all three: the same guarantee, said under its breath. The free answers — rise, flash, stamp — buy the legibility for nothing on the clock, but the deaf window still has to be built for them by hand.
